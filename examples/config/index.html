Configuration

Configuration belongs to the component, not to the bundle. Set a value and watch what it decides: whether a component runs at all, how many instances of it exist, and what its services publish. The bundles stay active throughout.

Values are kept in localStorage — reload the page and they are still here, which is the part of Configuration Admin the OSGi spec requires and leaves the medium of to the implementation.

Configuration

demo.tiles

RasterTiles · policy require

Nothing is registered until this exists. Delete it and the map bundle is parked, because its tile service loses its only provider.

demo.clock

SteadyClock and RestartingClock · policy optional

Two components on one PID. Only one has a @modified() method — change the interval and compare their tick counts.

demo.tile-source factory

TileSource · one instance per configuration

A factory PID turns the class into a template. Each configuration becomes its own instance with its own service registration.
